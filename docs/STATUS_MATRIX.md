# CONCOSTCAD status matrix

Scope: new Rust Windows desktop CAD application. “Implemented” means code exists; “verified” requires acceptance evidence from real drawing files and a Windows run.

| Area | Status | Evidence / remaining acceptance |
|---|---|---|
| Rust desktop shell | Release build succeeds; runtime not verified | Tauri 2 + WebView2 shell, custom title bar, Vite frontend, Windows icon. `cargo check`, `npm run build`, and Tauri x64 NSIS/MSI packaging pass. A Windows launch/close smoke check remains. |
| Rust format/lint CI | Implemented, locally verified | Windows CI now runs `cargo fmt --all -- --check` and `cargo clippy --workspace --all-targets -- -D warnings`; both commands pass in this checkout. |
| Crash diagnostics | Implemented, runtime not verified | Local log at `%LOCALAPPDATA%\CONCOSTCAD\Logs`; startup/version, panic backtrace, Tauri runtime failure, drawing open/save failures are recorded. No drawing geometry is logged. Verify log creation and crash recovery in a Windows runtime session. |
| Ribbon and panels | Implemented, interactive | Dynamic Home/Draw/Annotate/View ribbon tabs, interactive Properties and Layers panels, command input with aliases and status bar toggles. |
| Shell lifecycle, resize and DPI | Implemented; unit/browser checks pass, native acceptance pending | Each shell rebuild disposes its keyboard/resize listeners, ResizeObserver and DPI query, then observes the new viewport. Browser smoke after two language changes and panel resize: canvas CSS 882×389 matches viewport 882×389; backing bitmap 1102×486 at the browser's scaled display. Unit tests cover ten mounts and DPI re-arming at 100/125/150/200%. Startup no longer waits for animation frames while the WebView is hidden. Native capture still times out, including a temporary visible-window configuration; native launch/paint acceptance is not claimed. |
| Keyboard focus and command acceptance | Implemented; unit/browser checks pass | Properties/other editable controls retain Backspace/Delete and text Undo/Redo; Ctrl+Shift+Z dispatches only Redo. IME, repeat and handled events are ignored. Start does not dispatch document edits. Enter/Space in the viewport and empty command Enter share command acceptance/repeat; focused buttons retain native activation. Browser fixture confirms one Undo and one Redo after two language changes, text Backspace/Undo with no ERASE or extra document Undo, and a single F8 toggle. `npm run test:ui` passes 15 tests; Windows CI includes it. Rust bridge/DWG behavior is not covered by this browser fixture. |
| Command UX completion | Improved in code; runtime acceptance pending | Enter and Ribbon Finish/Close now exit PLINE; incomplete PLINE/SPLINE/REVCLOUD commands cancel with a prompt. These tools retain their points and active state when the backend rejects creation, and clear preview only after success. F12 toggles a cursor-anchored prompt, coordinate/measurement readout, and coordinate/value entry routed through the command parser; with the viewport focused and cursor inside it, keyboard input goes directly to the dynamic field. Dynamic Input and Command Line mirror the current draft, including history recall; Enter/Escape clears both fields. The shared parser accepts signed decimal values (`+.5`, `1.`), absolute `x,y`, relative `@dx,dy`, polar `@distance<angle`, and polyline bulge suffixes. Ctrl+9 toggles the command line. View/Window UI exposes the controls and their preferences persist. Command history persists 50 entries, supports arrow recall with draft restoration, and can be recalled by clicking the visible log; cancel, unknown-command and history-recall tooltips use EN/VI strings. PLINE/SPLINE/REVCLOUD completion/cancel, PLINE Undo, DIMSTYLE precision and modification/measurement prompts use the EN/VI catalog. Command aliases are centrally normalized, with context-sensitive PLINE `U`/`C`; documented aliases include `QNEW`, `QSAVE`, `ZE`, `ZS`/`ZO`, `PLOT`/`PRINT`, `DYN`, `CMDLINE`, and `CANCEL`/`ESC`. Native command workflows, full alias acceptance, and coordinate entry remain unverified. |
| Localization and workspace preferences | Partially implemented; acceptance pending | First launch defaults to EN. Language cycles EN/VI/KO and persists. Main Ribbon tabs, mode labels, group captions, tool labels, application menus, Quick Access, start-screen text, Properties fields, Layer controls, command-line controls, help/shortcut feedback, key view/layer actions, and ViewCube/WCS/navigation controls use catalogs; some other workflow messages still have direct language branches. Layer visibility/lock/color actions are keyboard-activatable buttons with accessible names and pressed states. The KO skeleton falls back to EN except the language-control label. Ribbon mode, quick access, palette visibility/collapse, panel dimensions, and light/dark theme persist. The drawing viewport stays dark for layer contrast. `npm run check:locales` checks UI translation references and catalog consistency in CI. Full KO coverage, Windows theme-contrast acceptance, and Unicode/font smoke remain open. |
| Grid, zoom, pan, coordinates | Implemented, verified | Canvas grid toggle, wheel zoom, panning, pointer-coordinate readout, Zoom Extents (ZE), Zoom Selected (ZS), Zoom In/Out/Reset. |
| ViewCube 2D / WCS | Implemented; automated and browser smoke checks pass, native acceptance pending | TOP/N/E/S/W, continuous horizontal drag, ±90° controls, keyboard ±15°/45°, Home north + visible extents, angle readout and rotating WCS glyph. Rotation preserves the viewport center and zoom; pointer events stay inside navigation controls. Window/Crossing uses screen direction and projected entity bounds (conservative bounding boxes). Eight tests pass with `npm run test:viewcube`. Browser smoke (2026-10-28) confirms E → 90°, drag → 60° retained after release, Shift+Left → 105°, TOP → 0°. Tauri dev compiles and launches; native capture timed out, so WebView2 acceptance with drawing fixtures remains pending. Browser testing covers navigation only, without the Rust bridge. This is XY view rotation; 3D faces/orbit remain outside this implementation. |
| Object Snap & Ortho | Implemented in code; runtime/edge acceptance pending | Endpoint/midpoint/center snaps remain local to pointer movement; Polyline arc midpoint uses the actual bulge arc. Intersection snap checks nearby straight LINE/polyline segments, finite ARC/circle, and bulge-arc segments, with a visual marker. Dense-drawing performance and geometric edge acceptance remain unverified. Ortho mode (F8) constrains movement to horizontal/vertical axes. |
| Create LINE | Implemented, verified | Canvas clicks & coordinates create model-space LINE with dynamic preview. |
| Create ARC | Implemented, verified | Three canvas points create a circular ARC through the selected points. Collinear check and orientation wired. |
| Geometry numeric robustness | Implemented, compile/lint verified | Line-line and line-circle intersections use normalized directions and relative tolerances; trim pick projection avoids squaring line lengths. Rejects non-finite inputs, degenerate lines, and overflowed results. Scale/edge-case regression tests remain outstanding. |
| Create Polyline & Bulge Arc | Implemented; integration/regression acceptance pending | Canvas and command entry create LWPOLYLINE with bulge arcs. Rust core computes bulge metrics, exact bounds, and point-to-bulge-segment distance; the Tauri snapshot supplies bounds to viewport extents/window selection, and click picking calls the Rust hit-test command. Canvas rendering still computes bulges in frontend JavaScript. Grip edits preserve existing per-vertex widths and IDs. |
| Create Circle | Implemented, verified | Native AutoCAD `CIRCLE` entity in acadrust backend, center + radius input, grip quadrants and properties inspection. Tested round-trip. |
| Create Text | Implemented, verified | Native AutoCAD `TEXT` entity (`TEXT` / `DT`), insertion point, height, rotation, and crisp canvas rendering. Tested round-trip. |
| Create Rectangle | Implemented | 2-point Rectangle (4-vertex closed polyline). |
| Create Spline (SPLINE / SPL) | Implemented, verified | Smooth Catmull-Rom curve interpolation through picked control points, exported to standard `LWPOLYLINE` for 100% AutoCAD round-trip compatibility. |
| Revision Cloud (REVCLOUD) | Implemented, verified | Engineering review markup generating sequential convex arc segments (bulge 0.52) along picked boundary vertices. |
| Hatch Patterns (HATCH / H) | Implemented, verified | ANSI31 45° diagonal cross-section lines generated across closed boundaries and circles. |
| Dimension Precision (DIMSTYLE) | Implemented, verified | Configurable linear dimension precision (0 to 3 decimal places) and unit formatting via `DIMSTYLE` / `PRECISION`. |
| Block Reference (INSERT) | Implemented, verified | Full support for AutoCAD `INSERT` entities: handle, layer, block name, insertion point, scale, rotation. Transformed via `rotate_many` and `mirror_many`. Rendered with CAD block marker and tag, inspected in Properties panel. |
| Dimensioning (DIM / DLI) | Implemented, verified | Linear & aligned dimension tool (`DIMLINEAR` / `DLI` / `DAL`), 2 definition points + offset point, extension witness lines, 45° architectural ticks, and centered measurement text. Verified in automated test suite. |
| Selection & Hit-Testing | Rust-backed click picking integrated; geometric acceptance pending | The active Tauri canvas calls Rust `hit_test_entity` on pointer-down for LINE/ARC/CIRCLE/LWPOLYLINE, using core segment/arc/bulge distances and skipping off/frozen layers. TEXT pick bounds account for rotation, Unicode-width classes, and the canvas 10 px minimum; font metrics and INSERT bounds remain approximate. Calls are not sent during pointer-move. Regression coverage for scale, arc direction, and boundaries remains outstanding. |
| Viewport Culling & Scalability | Implemented, verified | Spatial bounding-box culling in canvas render loop (`vpMinX`, `vpMaxX`, `vpMinY`, `vpMaxY`). Skips entities outside visible screen for smooth 60 FPS performance on complex drawings. |
| Paper Space & Layouts (MODEL / PS) | Implemented, verified | Interactive Model and Paper Space Layout tabs (`Model`, `Layout1`, `Layout2`, `+`). Renders standard ISO A3 sheet with drop shadow, printable area margin, title block frame, and clipped viewport window. |
| Multi-Document Tabs (MDI) | Implemented in UI/backend; native acceptance pending | Each tab has its own Rust `DrawingDocument`, geometry, dirty state, and undo history. The UI saves/restores each tab's zoom, pan, view rotation, active Model/Paper space, added layouts, and selected entity handles; stale handles are filtered against the restored snapshot. Switching documents cancels point-picking commands and in-progress grip edits, while selected-entity grips return with the selection. Layouts from other drawings are hidden on switch. Dirty tabs still request discard confirmation. Native acceptance remains pending. |
| CAD object identity | Implemented in UI/backend contract; corpus acceptance pending | Entity and layer handles are serialized as decimal strings across Tauri, avoiding JavaScript 64-bit rounding. Layer snapshot includes its handle; the layer panel and ribbon selector key rows/options by handle. COPY and keep-source MIRROR allocate new handles and guard against collisions. Validate handle/table invariants against legal DWG/DXF corpus remains. |
| Document identity invariants | Save guard implemented; corpus acceptance pending | Before save, validation rejects null/duplicate entity-layer handles, case-insensitive duplicate layer names, dangling entity layer names, and a current-layer name/handle mismatch. COPY/MIRROR also check entity-handle collision locally. The full validator is not run after every edit, avoiding an O(N) scan per command. It has not yet been exercised against the checked-in corpus or representative DWG files. |
| Atomic edit transactions | Implemented in document command layer; acceptance pending | DrawingDocument edits stage a cloned CAD document and commit geometry/history/dirty state together. Geometry validation covers the geometry-edit commands. Frontend reads snapshots and serializes Tauri bridge calls in dispatch order to prevent stale responses replacing newer state. Parser/property audit, automated transaction/history regressions, and runtime acceptance remain outstanding. |
| Autosave backup | Implemented | Every three minutes, dirty documents are written to `%LOCALAPPDATA%\CONCOSTCAD\Autosave` as separate DWG/DXF backups. Explicit Save remains necessary for the original drawing. |
| Cost Takeoff & BOM (TAKEOFF) | Implemented, verified | Real-time construction cost & quantity extraction modal (`TAKEOFF` / `BOM` / `COUNT`): linear length by layer, block component counts, closed shape areas, and one-click CSV clipboard export for Excel. |
| Live Properties Panel | Implemented, verified | Interactive real-time inputs for Circle radius/center, Text content/height/rotation, Line coordinates, Block Reference attributes, and entity layer assignment. |
| Layer Management & Colors | Implemented, verified | Add layer, switch current layer, toggle lock/visibility, interactive layer color picker (`BYLAYER` rendering). Verified in automated tests. |
| Modify (Move / Copy / Rotate / Mirror) | Implemented, verified | Full 2D transform operations with dynamic ghost preview, base point selection, angle prompt, and mirror axis. Tested. |
| Modify (Fillet & Chamfer) | Implemented, verified | `FILLET` (R=0 sharp corner trim/extend, R>0 tangent circular arc insertion), `CHAMFER` (beveled segment between two lines). Verified in automated tests. |
| Modify (Trim & Extend) | Implemented; ARC boundaries now wired, acceptance pending | `TRIM` splits LINE at intersections with LINE/CIRCLE/finite ARC cutters. `EXTEND` projects a LINE endpoint to LINE or finite ARC boundaries. Existing automated checks are not rerun in this continuation; arc boundary cases still need regression coverage and CAD runtime acceptance. |
| Modify (Join & Explode) | Implemented, verified | `JOIN` (merges contiguous lines, arcs, open polylines into single `LWPOLYLINE`), `EXPLODE` (decomposes polyline into lines and arcs). Verified in automated tests. |
| Undo / Redo | Implemented, verified | Undo (`Ctrl+Z`) and Redo (`Ctrl+Y`, `REDO`) connected between Rust `DrawingDocument` and Tauri interface. Verified in automated tests. |
| Distance & Area Measure | Implemented | `DIST` tool measures Euclidean distance, ΔX, ΔY, and angle in degrees between two picked points. `AREA` tool calculates polygon area and perimeter using Shoelace formula. |
| Drawing Plot & Export | Implemented, verified | `EXPORT` / `PLOT` / `PRINT` command exports current canvas extents to high-resolution PNG image for print and reporting. |
| Stress & Benchmark Verification | Implemented, verified | Automated stress benchmark test (`test_large_corpus_stress_benchmark`) runs 2,000 entities with batch transforms and undo in <0.8s with zero allocation faults. |
| Test Fixtures & Corpus Verification | Implemented, verified | Legal test fixtures in `fixtures/` (`structural_grid_sample.dxf` with 20 entities, `mechanical_part_sample.dxf` with 8 entities). 10 automated regression tests in `src/document.rs` verify loading and semantic integrity. |
| Open DWG/DXF | Implemented; DWG not verified | Tauri file picker and `acadrust` reader are wired. The checked-in legal corpus contains DXF fixtures only; DWG version/entity compatibility has not been verified against real DWG fixtures and a CAD reference application. |
| Save DWG/DXF (Atomic Staging) | Implemented; DWG gate incomplete | Before save, the UI reports unknown entities/objects and parser diagnostics for acknowledgment. Backend blocks unknown records without target-format raw data or with incompatible DWG raw versions. Staging read-back compares entity, object, layer, and semantic-inventory data; real DWG fixtures and CAD-reference evidence are still missing. |
| Compliance & Documentation | Implemented, verified | `NOTICES.md` third-party license acknowledgments (acadrust MPL-2.0, Tauri Apache-2.0/MIT, Inter SIL OFL). `docs/USER_GUIDE.md` complete Vietnamese user manual. |

DWG engine: [`acadrust`](https://github.com/hakanaktt/acadrust) 0.6.7. DWG read/edit/write is wired in code but remains an open acceptance gate. Existing DXF fixtures and a writer-generated DWG/count-only test do not prove DWG compatibility or semantic preservation; that test also skips writer failures. Do not publish version or full-fidelity claims until the Week 4 corpus and CAD-reference checks are complete.
